Lesson 7 · 18 min

Audio and captions in code: local narration, soundtrack, and karaoke

The same CLI that renders also speaks and listens, all on your machine: it generates the narration with a local voice, transcribes word by word with the timing of each one, and hands that to the composition. In this lesson you build the technical side of sound: narration, a rehearsal soundtrack, and the karaoke caption that lights up each word the moment it is spoken.

Start the lesson

In this lesson you will

  1. 1tts: text to WAV with the Kokoro voice, no cloud
  2. 2transcribe: the timing of each word in a transcript.json
  3. 3<audio> with id, data-start, and data-volume in the composition
  4. 4Captions of up to three words that light up on the beat of the speech

Goal: generate local narration, get the timing of each word, and render a video with audio and karaoke captions.

The default transcribe model in 0.8.176 is small.en, English only. For Portuguese, pass -m small -l pt: the multilingual small doesn't appear in the --help list (tiny.en, base.en, small.en, medium.en, large-v3), but it worked on this machine (screenshot alongside). And with --engine auto (default) the CLI uses Parakeet if it's installed and covers the language; without it, whisper.cpp.

File · kit/karaoke.py
#!/usr/bin/env python3
"""karaoke.py — turns transcript.json (word + timing) into legendas.js for the composition.

Usage:  python3 karaoke.py transcript.json --inicio 0.5 --por-linha 3 > legendas.js

--inicio     seconds at which the narration starts in the video (the <audio> data-start)
--por-linha  words per caption (default 3)
Prints to stderr: "palavras: N · legendas: M".
"""
import argparse
import json
import sys


def main():
    a = argparse.ArgumentParser()
    a.add_argument("transcript")
    a.add_argument("--inicio", type=float, default=0.0)
    a.add_argument("--por-linha", type=int, default=3)
    o = a.parse_args()
    palavras = json.load(open(o.transcript, encoding="utf-8"))
    linhas = []
    for i in range(0, len(palavras), o.por_linha):
        grupo = palavras[i:i + o.por_linha]
        linhas.append({
            "inicio": round(grupo[0]["start"] + o.inicio, 3),
            "fim": round(grupo[-1]["end"] + o.inicio, 3),
            "palavras": [{"t": p["text"], "inicio": round(p["start"] + o.inicio, 3)} for p in grupo],
        })
    # each caption leaves 0.15 s after the last word, but never after the next one enters
    for atual, prox in zip(linhas, linhas[1:] + [None]):
        atual["fim"] = round(min(atual["fim"] + 0.15, prox["inicio"]) if prox else atual["fim"] + 0.15, 3)
    print("window.LEGENDAS = " + json.dumps(linhas, ensure_ascii=False) + ";")
    print(f"palavras: {len(palavras)} · legendas: {len(linhas)}", file=sys.stderr)


if __name__ == "__main__":
    main()

The checker with --audio rejects a video with no sound track. The soundtrack is just a chord generated by FFmpeg for the rehearsal; yours goes in place of trilha.wav.

In the first version, each caption stayed 0.15 s after the last word even when the next one had already come in: two captions overlapped in the frame. karaoke.py now closes each caption at most when the next one opens. It only showed up by looking at the frames.
